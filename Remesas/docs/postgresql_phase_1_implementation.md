# Fase de preparación SQLite → PostgreSQL

## Decisión de seguridad

SQLite continúa activo por defecto (`database_backend.backend = sqlite`). Las herramientas PostgreSQL son comandos manuales y nunca se invocan al abrir la aplicación. No se accedió a `192.168.1.3`, no se ejecutó una migración real y no se incluyeron secretos.

## Fuente inventariada

La aplicación configura `C:\Liquidaciones\datos\liquidaciones.sqlite`. El fichero no está versionado ni disponible en este entorno, de modo que tamaño, conteos, extremos e inconsistencias de datos quedan pendientes de ejecutar sobre una copia autorizada. `python -m db_tools db inventory` genera el inventario real mediante `sqlite_master`, todos los PRAGMA de tablas/FK/índices, conteos, tamaño y SHA-256 sin volcar filas personales.

El esquema estático reconstruido de las 13 migraciones SQLite se documenta íntegramente en `postgresql_phase_0_inventory.md`. Sus 13 tablas funcionales se migran; no se detectaron tablas explícitas de caché. `schema_migrations` se sustituye por el registro PostgreSQL con checksum y no se copia como dato funcional.

## Mapeo

* `INTEGER PRIMARY KEY AUTOINCREMENT` → `bigint GENERATED BY DEFAULT AS IDENTITY`.
* UUID en `TEXT` → `uuid`; fecha → `date`; instante → `timestamptz`.
* importes/kilos → `numeric(18,6)`/`numeric(18,4)` y precios/factores → `numeric(18,10)`.
* booleano 0/1 → `boolean`; JSON textual → `jsonb`; texto libre → `text`.
* Identificadores históricos se insertan explícitamente. Antes del corte definitivo se deberán reajustar las identities con `setval` una vez validados los máximos.

No se han inventado tablas de anulaciones o rectificaciones: el modelo real las representa mediante `operation_type`, estados y relaciones de batches/líneas.

## Migraciones

Los archivos `001`–`007` crean exclusivamente `liquidaciones`, tablas core, documentos, contabilidad, auditoría/progreso, índices y finalmente el índice único parcial. La última migración se niega a instalarse si encuentra duplicados y no corrige datos. El ejecutor usa SHA-256, transacciones y advisory lock.

## Comandos (desde `Remesas`)

```console
python -m db_tools db inventory --source 'C:\Liquidaciones\datos\liquidaciones.sqlite' --output sqlite_inventory.json
python -m db_tools db migrate
python -m db_tools db migrate-data --source 'C:\Liquidaciones\datos\liquidaciones.sqlite' --target postgresql --dry-run --report-dir migration-report
python -m db_tools db validate --source 'C:\Liquidaciones\datos\liquidaciones.sqlite' --report-dir migration-report
python -m db_tools db rollback-test --run-id UUID
```

La contraseña sólo procede de `POSTGRES_PASSWORD`. Para cargas destructibles debe apuntarse a un esquema temporal aislado; `rollback-test` elimina sólo metadatos de ejecución y deliberadamente no borra filas funcionales sin trazabilidad por fila.

## Riesgos pendientes

1. Falta ejecutar el inventario contra una copia real y completar conteos, máximos, nulos, huérfanos y sumas económicas reales.
2. La primera carga completa debe hacerse en un esquema temporal; no se ha probado conectividad ni permisos centrales.
3. Deben verificarse precisión máxima y formato real de UUID/fechas/JSON antes de carga.
4. El migrador inicial conserva valores y detecta conflictos por PK, pero la reanudación por `last_key`, el reajuste automático de identities y las agregaciones económicas completas requieren endurecimiento antes del corte.
5. Los repositorios PostgreSQL son deliberadamente iniciales y no sustituyen aún los repositorios SQLite productivos.
